# Library/Catalog + Interaction Audit

**Baseline:** Package.swift:55-70 declares test targets for LumenCoreTests and LumenPipelineTests only — **there is NO test target for LumenApp**, so no keymap, culling, filter-mapping, prefetch, quit-flush or slider behaviour has any test that can fail. That fact recurs throughout.

## LIBRARY / CATALOG
- **LIB-01 — photo.quick_sig still has NO PRODUCER: rename/move = silent data loss.** BROKEN. CatalogService.registerAndLoad builds every ScannedFile without a signature (:87-89); the only quick_sig mentions in the repo are the DDL (Schema.swift:37,53) and CatalogStore itself. The move-detector (CatalogStore.swift:1301-1311) therefore always sees nil and falls through to upsertPhoto + missing=1 (:1328-1340): a renamed or moved original becomes a fresh photo and its rating, flag, label, album membership, stack membership, history and edit rows stay stranded forever. Against README principle 6. **Precise cost:** hash primitive exists (XXH64.hash, Fingerprint.swift:15). Needed: (1) quickSignature(url:)->String — first 1 MB + size, "xxh64:" prefix, ~20 lines in LumenCore; (2) a producer **in the background backfill pass, not the scan** (hashing 5,000 × 1 MB on open would bust the first-grid gate) — extend backfillMetadata (:134-164) plus setQuickSig(photoID:), ~30 lines; (3) populate inline for NEWLY SEEN files in registerAndLoad; (4) two store tests: rename-inside-folder and move-across-folders both relocate with edits intact — the scan() relocation branch is currently UNTESTED. **~80-110 lines total.**
- **LIB-02 — Preview/artifact cache on disk: still completely unwired; thumbnails re-decode every launch.** MISSING. ThumbnailLoader is a pure in-memory LRU keyed (url, pixels) (:96-99), no CatalogService reference, no photo_id, no disk write. recordPreview/preview/touchPreview/invalidatePreviews/pruneCache (CatalogStore.swift:1883-1987) and recordArtifact/pruneArtifacts (:1998-2105) have ZERO app callers. Consequences: every launch re-decodes every embedded JPEG; the preview.source embedded/lumen distinction driving the camera-render honesty badge is dead; the docs/15 §15.6 ladder (thumb 256/grid 1024/fit 2560/1:1) does not exist — buckets are 256/512/1024/2048, no fit, no 1:1 tiles. **Directly against README goal #1 and PM's bar.** Wiring: inject CatalogService (or a PreviewStore facade) into ThumbnailLoader.init (created in AppState:755 where catalog also lives); map URL→photo_id via the StoredState dict registerAndLoad already returns; on decode-finish encode HEIC to previews/xx/, call recordPreview; on lookup miss consult preview(photoID:level:) before scheduling a decode; run pruneCache from the quit path. docs/18's ~100-line estimate is right, PLUS it needs a LumenAppTests target or a LumenCore seam to satisfy condition 3.
- **LIB-03 — Raw-truth instruments absent: no raw histogram, no clipped-%, no boost/inspect holds.** MISSING. RawStatistics exists with full binning/encode/decode (Scopes.swift:497-620) and its only callers are two blob round-trip tests — tests that still pass if the feature never ships. No CFA/LibRaw reader anywhere in LumenPipeline, no raw_stats writer, no ⇧H panel, no per-channel clipped-% readout, no [/] shadow-boost/highlight-inspect holds ([/] are thumbnail size), no raw-clipping overlay. **README measurable goal #3 and the FastRawViewer pillar — the one claim FRV alone owns — and none of it reaches the UI.** The develop-side histogram bins the RENDERED image, exactly the "histogram that lies" docs/10 §10.5 exists to beat.

- **LIB-05 — Backup is a manual menu ritual with no rotation, no auto-on-quit, no pruning.** PARITY-GAP. - **LIB-06 — Virtual copies and snapshots: schema-only; saveRecipe writes only .working; the version filter can never match.** MISSING. Days, not hours.

- **LIB-08 — Sidecar conflict rules unimplemented: a newer sidecar loses to a stale catalog, then gets OVERWRITTEN.** BROKEN. photo.sidecar_mtime has NO WRITER so docs/15 §15.5's three mtime-keyed rules cannot run. ## UX / INTERACTION / PERFORMANCE
- **UX-01 — The latency contract has ZERO instrumentation: no five-loop gate, no measurement of any budget.** UNPROVEN. docs/12 §12.2 makes the five loops "release gates measured in CI with hard numbers" and the README calls them the moat. No measure(/XCTMetric/signpost anywhere in Tests, no scripts measuring input→photon, paging or scroll hitches, and no Mac has ever run the app. **Every claim in docs/19 Phase 1 is a code-inspection claim.** What to measure: os_signpost at NSEvent receipt → CIContext render completion for the slider loop; arrow-keydown → first PhotoRenderModel.apply for paging; XCTOSSignpostMetric.scrollDecelerationMetric on a 10k grid; assert ≤16.7 ms / <50 ms / 0 hitches.
- **UX-02 — The prefetch ring warms the WRONG cache level for loupe paging.** BROKEN. The loupe's instant path asks the thumbnail cache at maxPixel:1600 → bucket **2048** (LoupeView.swift:331-334), but the ring prefetch is only ever invoked at filmstrip size 256 (FilmstripView.swift:24,68,78) and grid cell size. The filmstrip's own comment claims the ring "warms exactly the frames paging is about to reach" — FALSE for the view paging actually happens in: every loupe advance pays a cold 2048-class embedded-JPEG decode plus the full pipeline render. **This is the mechanism behind README goal #1, defeated by a units mismatch between requester and prefetcher.**
- **UX-03 — The full-quality refine cannot meet its own 200 ms budget by construction.** BROKEN. PhotoRenderModel sleeps settleNanoseconds=250 ms THEN starts the quality render (LoupeView.swift:285-288, 361-378), so full quality lands at 250 ms + render time; docs/12's budget is "full quality ≤200 ms after drag pause". The comment claims 250 ms "is the settle window plus the pass itself" — the code contradicts it (sleep precedes the pass).

**Summary against the four conditions:** the **catalog STORE layer** (identity, culling persistence, filter/sort SQL, subsec, stacks-in-SQL, XMP merge discipline) is the genuinely strong half — conditions 1-4 largely hold with real failing-capable tests. The **app layer above it** passes conditions 1 and 2 for wired features but fails condition 3 WHOLESALE (no test target), and the library's headline pillars — raw truth, preview persistence, move-safety, ingest, AI assists, versions/snapshots, watching — fail condition 1 outright: the store exposes them and the app does not call them, precisely the pattern docs/18 was written to end.
