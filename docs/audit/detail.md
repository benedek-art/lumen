## Classical denoise
- **DETAIL-13 — Colour at 100 is WORSE than Colour at 25 on both residual error and colour-edge survival; the code has not changed since measurement.** BROKEN. docs/19 (ISO 6400): RMS off 0.0180 → 25: **0.0097** → 100: **0.0126**; saturated colour edge (clean 0.5200) at 100: **0.3364** — 35% gone. The measurement (faf4f33) postdates the chroma remap (3079220) and the only later DenoiseEngine commit merely restored the edge map in force at measurement time — the numbers stand. Mechanism: chromaK(100)=4.0σ (DenoiseEngine.swift:575-579) annihilates every chroma band (0.1% kept per the file's own table) while chromaProtection=colorDetail/100 (:1153) caps at 1.0 and the coarse-band multiplier 1+3.0·smooth·coarse (:795-807) pushes thresholds higher. Fix shape: bound the useful travel (chromaMaxK≈3, or protection that scales with k), and make edge retention a tested invariant. LR's manual Color slider does not destroy colour edges at 100.
- **DETAIL-14 — Luminance gives back gain past ~50.** BROKEN (mild). RMS 25: 0.0150, 50: **0.0145**, 75: 0.0149, 100: 0.0154; fine-band correlation with real texture falls 0.155→0.025 over 50→100. Not a wiring defect — lumaK is monotone and the GPU matches the reference to 2e-4.
- **DETAIL-15 — No test measures denoise QUALITY against ground truth, so DETAIL-13/14 sit behind a green suite.** UNPROVEN. DenoiseTests.swift:91-133 asserts noise-σ falls monotonically with the slider — which stays true while SIGNAL is being destroyed; residual-error-to-clean and edge-survival are asserted nowhere. The GPU goldens prove GPU==reference; nothing proves the reference is GOOD. The harness exists (noisyFrame already carries a clean base, an edge and a colour line).
- **DETAIL-16 — ISO-adaptive Colour defaults resolve INTO the measurably-harmful region.** BROKEN (compound of 13). colorAnchors (DenoiseEngine.swift:1553-1558) resolve ISO 6400 → Colour **40**, ISO 25600 → **55**; measured optimum ≈25 and everything above is worse on both axes. The flagship "profiled and ISO-adaptive rather than fixed" departure from LR hands every high-ISO raw import a Colour setting worse than LR's flat 25 it claims to beat. (Wiring itself is correct and tested; JPEG lie fixed.)
- **DETAIL-17 — "Profiled" denoise has NO profiles: one generic seed curve for every camera; self-calibration written and uncalled.** PARITY-GAP. Shipping profile is always NoiseProfile.forISO(captureISO ?? 100) (RenderPlan.swift:279) — a two-parameter seed curve identical for every body; NoiseProfile.estimate(from:) (DenoiseEngine.swift:139) — the docs/07 "estimated on first encounter from flat regions and cached in the catalog" mechanism — has zero callers. The panel note "Profiled wavelet noise reduction" and docs/07's "calibrated to the sensor" overstate. darktable's per-(camera,ISO) measured profiles are the classical benchmark; every threshold in Lumen is denominated in a σ that may be wrong by a factor for any given sensor.
- **DETAIL-18 — Hot Pixels passes all four conditions.** THE DOMAIN'S CLEAN PASS. Reaches pixels, UI reachable, tests that can fail (spike removed, dark spike removed, one-pixel line preserved, network==reference to 1e-4), nothing lies. C1-parity nicety delivered.
- **DETAIL-19 — The four sub-sliders wired, goldened, honest.** PASS, one caveat: behaviour vs the LR contract they clone has never been compared against actual LR output; only self-consistency is tested.
