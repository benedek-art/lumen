## Mixer
- **COLOR-01 — Band names sit up to 22° off the colours they name.** PARITY-GAP. ColorEngine.bandAnchorDegrees=29.23, spacing 45° (ColorEngine.swift:98-111). sRGB orange=53.0° vs "Orange" centre 74.2°; sRGB green=142.5° vs "Green" 164.2° — pure green lands EXACTLY on Yellow/Green core boundary; foliage (135°) is inside YELLOW's core. Dragging "Green" moves foliage at ~half authority. LrC/DxO place wedges on perceptual colour names (docs/02 §2.8, docs/03 §2.4). Measure: band membership weight of sRGB green/orange/foliage per band.
- **COLOR-02 — No mixer eyedropper, no TAT.** MISSING. `PickTarget` has no mixer-band case (AppState.swift:90-106); no targeted-adjustment drag anywhere (only doc comment ViewerOverlays.swift:306). docs/05 makes eyedropper "the primary entry"; docs/02 §2.8 records TAT as the interaction LrC users consider "the right one".
- **COLOR-03 — Mixer band Hue/Sat/Lum (24 controls) have no behavioural test.** UNPROVEN. Only non-default MixerBand(hue:) in tests is the malformed-recipe guard (RobustnessTests.swift:667); everythingRecipe has no mixer values (RobustnessTests.swift:1345-1393); ScaleHonestyTests:97-100 asserts only scale-invariance which identity satisfies. Delete hueSum/satSum/lumSum from applyMixer (ColorEngine.swift:839-863) → suite stays green. Headline claims vs LrC (chroma-held Luminance, hue-stable Saturation) asserted by nothing.
- **COLOR-04 — Mixer Luminance (and Point Colour Luminance) dies above scene white.** BROKEN. Shaping term `shaped·(1−shaped)`, `shaped=saturate(L)` (ColorEngine.swift:860-862, swatches :969-970): ZERO effect at OKLab L≥1 (~+2.5 EV over mid-grey), ~1/3 authority at L≈0.9 — bright skies, lit clouds, sunlit skin. Stage runs pre-display-transform on unbounded data. The file's own comment on satRolloffHi0 (:205-216) states the rule being violated. LrC darkens bright skies at full strength (docs/02 §2.8). Measure: Blue-band Lum −100 on patches at +1/+2/+3 EV.
- **COLOR-05 — Uniformity is one global slider, captioned as per-band.** FAKE(caption)+PARITY-GAP. Single Mixer.uniformity (Recipe.swift:264-272); engine applies to all eight bands (ColorEngine.swift:839-854). Panel sits under band selector, captions "converges THIS BAND's hues" (ColorPanel.swift:94-105). DxO's Uniformity is per-channel (docs/03 §2.4).
- **COLOR-06 — Uniformity converges on wrong target: bandMeanHues has a writer nothing ships.** UNPROVEN/PARITY-GAP. measureBandMeanHues exists+tested (ColorEngine.swift:605-684; ColorScienceTests.swift:685-780) but only callers are tests; both RenderPlan constructions build ColorEngine without it (RenderPlan.swift:126-128, 354-355). Shipping Uniformity converges on core-arc midpoint, not measured mean. docs/05 specifies chroma-weighted mean hue of band members (= DxO behaviour). Wiring spelled out at ColorEngine.swift:63-67.
- **COLOR-07 — Texture-preserving half of Uniformity/Variance absent on shipping path.** PARITY-GAP (docs/18 claim VERIFIED still true). apply(_:) passes the pixel as its own local mean (ColorEngine.swift:309-337); kernel degrades to whole-pixel movement (:552-559). LrC Variance compresses colour "while preserving texture" (docs/02 §2.9); C1 skin uniformity likewise (docs/03 §1.4). WORSE on expand side: with μ=pixel, positive Variance amplifies each pixel's own deviation = amplifies chroma noise. Wiring plan in code at ColorEngine.swift:324-336.
- **COLOR-08 — Band-weight ribbon exists; image-space "show reach"/"show change" and Alt-drag do not.** PARITY-GAP. MixerBandRibbon (ColorPanel.swift:832) draws over hue axis not image. darktable's two toggles called "the killer feature" in docs/03 §6.1.
- **COLOR-09 — Hue-Selective Equalizer does not exist.** MISSING (docs/18 VERIFIED still true). No curve face in Sources (only comments ColorEngine.swift:101-102). docs/05 Doctrine 1 makes it the Mixer's second face; the "Vs. the field" table claims "✓ + per-mask + curve face" — the curve-face third is false.

## Skin

- **COLOR-24 — Skin TOOLS still one-third built: no uniformity tool, no target picker, no batch guardrail.** MISSING — this is the named bar to beat. - **COLOR-25 — Protect Skin at its default silently breaks "Saturation −100 = B&W".** BROKEN. protection = 1 − protectSkin/100 × skinWeight multiplies the NEGATIVE satAmount too (ColorEngine.swift:1033-1040), so at shipped default 70 (Recipe.swift:119) full desaturation leaves skin-hued pixels at ~70% chroma. Contradicts the wire format's contract ("−100 reaches true B&W", Recipe.swift:114), the engine's own in-code claim (ColorEngine.swift:1036-1037), and LrC muscle memory (docs/02 §2.4).
- **COLOR-26 — Protect Skin's attenuation path has no test.** UNPROVEN. - **COLOR-27 — Masked local Sat/Vibrance inherit invisible defaults: density 50, protectSkin 70, no local control.** UNPROVEN. Both local paths construct ColorAdjust(vibrance:…, saturation:…) leaving other fields default (RenderGraph.swift:1476-1477; ReferenceRenderer.swift:250-254).
