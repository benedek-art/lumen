# Masking Audit

## THE CRITICAL PRIOR FINDING — verdict
docs/18's hole ("no test anywhere puts a mask through RenderGraph") is **substantially closed but not fully**. `testAMaskReachesPixelsThroughTheGraph` (KernelGoldenTests.swift:189-330) now drives a vertical linear-gradient mask through RenderGraph.build with a scene-referred exposure lift AND a display-referred point curve. It compares the GPU exposure tap against ReferenceRenderer exactly (worst <0.02), asserts the selected end moves >3× the unselected end (catching flat, inverted, or **vertically mirrored** raster through the CIImage(bitmapData:) bridge, since the mask varies down the frame), and asserts the curve tap separately. Deleting applyLocal (RenderGraph.swift:111-113) or applyLocalCurves (:162-164) fails this test. applyLocal, applyLocalCurves, LocalCurvePlan, maskImages and vector-raster orientation are no longer collectively unasserted. **What remains open is MASK-01.**

- **MASK-01 — PipelineRenderer.makeGraph, the ACTUAL shipping mask wiring, has no test.** UNPROVEN. The golden builds its own RenderGraph, calls MaskRaster.combine itself, sets graph.maskImages by hand (KernelGoldenTests.swift:219-226). No test calls renderPreview or export with a mask. So PipelineRenderer.swift:496-546 — the maskSource stage-input computation (604-641), per-mask rasterization with strokeSets/aiMattes, and graph.maskImages population — can regress with the suite green. Exactly the shape of the shipped bug the code records ("This used to be nil… Luma Range, Colour Range and both Similarity kinds returned nothing" — :512-524).
- **MASK-02 — Masked colour work EXPORTS at preview table size.** BROKEN. LocalPlan always bakes at LUT3D.interactiveSize (33): RenderGraph.swift:1506, and applyLocalAdjust constructs it with no size argument (:837), while export runs at exportSize (65) and the local CURVE correctly receives options.lutSize (:890). By docs/18's measured table, size 33 is 0.197 stops worst-case with 10.6% of samples over 0.02 EV vs 0.074 at 65 — every masked contrast/temp/hue/sat/vibrance/point-colour/wheel edit in a delivered file carries preview-grade error. LR does not degrade local adjustments on export (docs/02 §3.3).
- **MASK-03 — 15 of 17 local sliders are unproven on the shipping path.** UNPROVEN. testEveryLocalSliderThePanelOffersChangesThePicture (RobustnessTests.swift:199) drives 16 local fields through **ReferenceRenderer only**. On the GPU path the golden drives only exposure and the curve. Delete balance.apply(c), colorEngine.apply(c), the hue rotation, applyColorTint, or localGrade.apply(c) inside LocalPlan (RenderGraph.swift:1506-1528), or the presence/sharpness block in applyLocalAdjust (:846-873) — suite stays green. The seven-dead-sliders history happened on precisely this seam.
- **MASK-04 — Every draft frame drops ALL masks entirely.** PARITY-GAP. makeGraph returns an empty graph for drafts (PipelineRenderer.swift:501 `guard !draft else { return graph }`) and S11/S15b are !draft-gated (RenderGraph.swift:111, 162). The loupe renders draft-first on every edit with a 250 ms settle, so while dragging *a mask's own slider* the picture shows the recipe with the mask's effect ABSENT, then snaps back. LR's masking is slow but renders local adjustments live while dragging (docs/02 §3.4 complains of lag, never absence); docs/08 §8.1 budgets ≤16.7 ms.
- **MASK-05 — The Whites/Blacks panel caption is FALSE.** FAKE. MaskPanel.swift:544-546 says "Whites and Blacks reshape where Highlights and Shadows act in this mask; on their own they do not move the picture." But ToneEngine.zonalStops gives Whites and Blacks their OWN shelves — whites*whiteToneEV*whiteWeight(t) (ToneEngine.swift:272-280), added because anchor-only Whites was "a slider a photographer would call dead" (:300-305). LocalPlan feeds local whites/blacks into that same engine (RenderGraph.swift:1471-1476), so a mask with only Whites +100 moves the top of the range by up to 1.3 EV. The caption describes a PREVIOUS engine. No test covers local whites/blacks on either path.
- **MASK-06 — Adding a second Vision mask kind after the first pass never computes its matte, and the panel then lies about why.** BROKEN. The "attempted" ledger is per-FILE not per-KIND: AppState.ensureMaskMattes bails on attemptedMattes.contains(url) (AppState.swift:583), RenderCoordinator.ensureMattes bails on hasAttemptedMattes (:196), export-inline has the same guard (:169). Add Subject → pass runs {aiSubject} → later add People → every guard short-circuits; the People matte is never generated for preview OR export. matteStatus then reports .notFound and the panel prints "Vision found no person in this frame" about a request never made.
- **MASK-07 — The 12-file matte LRU desyncs from the app's ledger; evicted subject masks render EMPTY while the panel says ready.** BROKEN. PipelineRenderer evicts mattes past 12 files (:62, 83-86) but AppState.attemptedMattes/availableMattes are never trimmed (:538-543, no removal anywhere). Browse 13+ photos with Vision masks and return to the first: ensureMaskMattes early-returns, the render reads mattes[url] ?? [:] and Subject rasterizes to ZERO (MaskRaster.swift:592), while matteStatus still returns .ready from the stale ledger. Export is safe (its guard reads the renderer's own cache); preview is not.
- **MASK-08 — Sky mask: LR has it, Lumen renders empty.** MISSING. matteProvider == .model, no model ships (RecipeMasks.swift:141-144). Honest, but LrC 15.5's Select Sky is one click (docs/02 §3.2) and docs/08 §8.3 calls Sky table-stakes — including the doc's own core test case "Sky ∩ Luminance, minus a brush", whose first leg selects nothing.
- **MASK-09 — Object selection: LR ships Brush/Rectangle Select; Lumen ships nothing that computes.** MISSING. SAM not bundled; aiObject renders empty. docs/02 §3.2 and docs/03:727 (darktable 5.6 SAM click-to-mask) both ship today.
- **MASK-10 — The Object row's prompt affordances are inert by construction.** FAKE. The row prints "N prompt point(s)" and offers Reset (MaskPanel.swift:369-374) but NOTHING writes MaskComponent.prompt — MaskCanvas.isLive excludes aiObject (:172-178) and the only .prompt reference in the app layer is that display. The count can never leave 0; Reset resets nothing.
- **MASK-11 — Landscape classes: LrC has 8, Lumen has 0.** MISSING. No model, honest note, class toggles correctly removed.
- **MASK-12 — Depth Range selects nothing on any file.** MISSING. No estimator and embedded depth is not read; depthRangePlane guards on the missing map (MaskRaster.swift:566-569). LrC's Depth Range at least works on iPhone-HEIC (docs/02 §3.2); Lumen's spec claims "better than LrC because ours works on every raw" (docs/08 §8.3) and the shipped truth is strictly worse than the gimmick.
- **MASK-13 — People: one union matte for everyone; LrC has per-person chips plus 10 sub-regions.** PARITY-GAP. VNGeneratePersonSegmentationRequest returns one matte for all (VisionMattes.swift:121-137). The sixteen inert checkboxes were correctly removed (personParts/classes now have neither writers nor readers, absence disclosed MaskPanel.swift:340-352).
- **MASK-14 — Subject: no instance chips, no quality/matting pass.** PARITY-GAP. All foreground instances unioned because "instance CHIPS… are a component field the wire format does not have" (VisionMattes.swift:99-101); the BiRefNet hair-matting pass of docs/08 §8.3/§8.8 does not exist. LrC 15.4's Select Subject picks instances.
- **MASK-15 — The whole Vision path has never run; the CVPixelBuffer orientation is an argument, not an observation.** UNPROVEN. VisionMattes is #if os(macOS) and the file says it "cannot be compiled on the machine it was written on" (:111-112); orientation contract is a comment (:19-24). If the buffer arrived bottom-up, plane(from:) (:146-178) would produce a vertically mirrored subject matte — on a portrait, the "subject" darkening the floor — with Background complement equally wrong, nothing failing. **Two headless tests would settle it:** (a) synthetic CVPixelBuffer (top rows 255, bottom 0), assert plane(from:) puts mass at Plane row 0 — no Vision needed, runs on any Mac; (b) fixture photo with subject in a known corner, run generate, assert matte centroid lands there. Neither exists.
- **MASK-16 — Background-is-the-complement coded as claimed but unasserted.** UNPROVEN. `out[aiBackground] = subject.map { 1 - Num.saturate($0) }` (VisionMattes.swift:83-87). The line lives inside generate which requires Vision, so no test can fail on it; a refactor could make Background a copy of subject and stay green. A pure unit seam (inject the subject plane) makes it Linux-testable.
- **MASK-17 — Similarity Point has no point: the U-Point mechanic is missing its spatial half.** PARITY-GAP. MaskComponent stores no point geometry, radius or ± sign, so the gate "evaluates over the whole frame" — engine (MaskRaster.swift:505-511 "DEGRADED") and panel (:413-414) both admit it. DxO's Control Point is chroma+luma similarity WITHIN A RADIUS with negative points (docs/03:300-303); the shipped control is functionally a Gaussian colour range. The scorecard row "Similarity point/line: yes" (docs/08 §8.11) overstates.
- **MASK-18 — Manual-component differentiators have no wire fields: linear Mirror, colour-range per-axis tolerances, per-sample delete.** MISSING. Mirror (MaskRaster.swift:327-328 "no shipped field"); per-axis tolerances linked-only (:458-459, disclosed MaskPanel.swift:406-408); sample removal is last-only (:753-760) where LrC deletes per chip. Credit: 8 samples beats LrC's 5.
- **MASK-19 — Luminance Range: sliders instead of the instrument.** PARITY-GAP. Shipped: Band Lo/Hi/Smoothness sliders. LrC has trapezoid handles over a live luminance histogram, **Show Luminance Map**, and an eyedropper (docs/02 §3.2); spec promises all three plus EV denomination (docs/08 §8.2). Only the EV denomination shipped.
- **MASK-20 — Brush: pressure hardcoded, eraser is a mode toggle, none of the brush keys exist.** PARITY-GAP. Every point carries pressure:1 (MaskCanvas.swift:396) though wire format and spec promise NSEvent pressure; eraser is a checkbox sharing one parameter set where LrC's Alt-eraser remembers its own Size/Feather/Flow; `[`/`]`, Shift+brackets, digit flow, A, hold-Alt erase all absent. Cursor draws size ring but not feather ring (:481-487). **Credit:** vector strokes with Catmull-Rom + arc-length stamping, Flow/Density asymptotic semantics, Automask actually wired on the shipping path (PipelineRenderer.swift:607-620).
- **MASK-21 — The refinement chain never touches full resolution, so no mask holds at 100% zoom.** PARITY-GAP. Refine/Edge/Feather/Levels run inside MaskRaster.combine at the 1024 px raster (PipelineRenderer.swift:507-535, 649), then bilinearly stretched (:652-674). docs/08 §8.5 specifies the OPPOSITE — "only the refine step touches full resolution, lazily per zoom tier" — because that is what makes a 1024 px matte hold on a 61 MP file. On a 9504 px export every mask edge is a ~9× upsampled ramp. LrC's masks are full-resolution rasters. Measure: export 6000 px with a hard luma band + Refine 50, measure edge transition width (~6 px where spec demands ~1).
- **MASK-22 — Colour-range/similarity samples picked from a DIFFERENT pipeline tap than the one the mask compares against.** BROKEN. The eyedropper stores sampleWorking — decoded pixels through the S6 matrix only (RenderCoordinator.swift:239-252, PipelineRenderer.swift:820-830) — but colorRangePlane/similarityPlane compare those refs against localStageInput, which additionally includes S7 tone and the S9/S10 colour+grade table (RenderGraph.swift:70-104). With any real global tone/colour edit the clicked colour and the compared colour diverge, so the mask can fail to select the very pixel that was clicked.
- **MASK-23 — Stroke blobs are not guaranteed at export; the one guard written for this has NO CALLERS.** BROKEN. Batch export builds jobs from strokeSets(for:), memory-only by design (AppStateActions.swift:134-137; AppState.swift:1283-1298). Blobs load via a detached task at catalog open (:1501-1503), so an export racing that load — or any unreadable blob — silently rasterizes brush components EMPTY in the delivered file, the exact ".lrcat-data black mask" failure docs/08 §8.7 exists to prevent. `strokesAreResolved(for:)` (AppState.swift:1328) was written to distinguish "no strokes" from "bytes unreadable" and nothing calls it. (The in-canvas destroy-previous-strokes defect IS fixed.)
- **MASK-24 — "Colour tint" desaturates.** PARITY-GAP. No picker writes colorTint; toggling hardcodes mid-grey (MaskPanel.swift:565) against which applyColorTint mixes toward neutral — help text admits it (:574-577). LrC's local Color tint swatch actually tints.
- **MASK-25 — Local Noise, chroma NR, Moiré, Defringe, Grain: five wire fields, zero readers, honest panel.** MISSING. RecipeMasks.swift:283-289; no readers on either path; LocalNoiseAdjust (DenoiseEngine.swift:1677) also has no caller — docs/18 VERIFIED TRUE. Panel hides them and says why (MaskPanel.swift:702-708). LrC ships all four locally (docs/02 §3.3).
- **MASK-26 — No mask pins, no Amount pin-scrub.** MISSING. No pin anywhere on the canvas; LrC scrubs per-mask Amount by Alt-dragging the pin (docs/02 §3.3), docs/08 §8.1 clones it. Amount sliders themselves are real, correctly clamped and pinned by maskalgebra.json.
- **MASK-27 — Overlay grammar: modes and keys shipped and tested; per-mask colour, auto-show, Alt-drag matte previews absent.** PARITY-GAP. Real: six modes composited from true alpha against the sampled picture through the geometry inverse (ViewerOverlays.swift:493-650), tested mode-by-mode plus cycle-order (MaskingTests.swift:317-407), O/⇧O/⌥O/' bound. Missing vs docs/08 §8.6 and LrC: per-mask colour swatch (one global tint only), auto-show on hover/create + auto-hide while dragging, the pervasive "Alt-drag any refine slider shows the matte" micro-interaction.
- **MASK-28 — The geometry inverse that places every gesture and overlay is UNTESTED.** UNPROVEN. sourceNormalized/displayedNormalized/displayedPixelsPerSourcePixel (PipelineRenderer.swift:875-930) are load-bearing behind MaskCanvas (:542-562), overlay reprojection (ViewerOverlays.swift:599-616), and the cursor-ring-vs-painted-width guarantee (:495-502) — the exact seam of the prior cropped-frame defect. ZERO test hits. A flip/rotate ordering regression would re-displace every gesture on cropped photos silently. Also LoupeView.swift:737-738 falls back to the CROPPED preview size for sourceSize until primaryFrameSize loads — a brief window where the fixed bug's geometry recurs.
- **MASK-29 — No raster caching: every settled frame re-rasterizes every mask on the CPU; the artifact table is unused.** UNPROVEN (performance contract). makeGraph runs MaskRaster.combine per mask per settled render (PipelineRenderer.swift:529-539) — guided-filter refine, EDT edge shift, Gaussian blur at 1024 px per frame; nothing caches component or folded planes; CatalogStore.recordArtifact has no callers. docs/08 §8.7's ≤16.7 ms drag and ≤100 ms photo-switch budgets are claimed "measured in the CI release gate" — no perf test exists in either suite. docs/18 VERIFIED TRUE.
- **MASK-30 — Adaptive presets and mask copy/sync don't exist.** MISSING. No user preset embeds masks, no copy/paste-settings path. LrC ships Adaptive Presets whose AI masks recompute per photo, plus Copy/Paste including masks (docs/02:476-492); docs/08 §8.10 claims this as a headline.
- **MASK-31 — Keyboard grammar is a fraction of the cloned-from-LR spec.** PARITY-GAP. Shipped: M (panel — spec says Shift+W), O/⇧O/⌥O, '. Absent: Shift+W, K brush, M linear, Shift+M radial, brackets, digits, A, hold-Alt erase.
- **MASK-32 — Component/mask housekeeping short of LrC: no reorder, no thumbnails, no Duplicate-and-Invert.** PARITY-GAP. Stack folds in creation order with no move control and no per-component thumbnails (MaskPanel.swift:230-255); mask menu offers Duplicate/Delete only. **Credit:** eye toggle, rename, per-component op editing (a genuine visible-Intersect win over LrC), per-component invert with '.
- **MASK-33 — The XMP "masks survive catalog loss" contract is BROKEN for brush masks.** PARITY-GAP. The sidecar carries the full recipe JSON incl. mask parameters (XMPSidecar.swift:8, 35-36) but brush components store only strokesRef and blobs are not embedded. docs/08 §8.9 specifies stroke lists ride in the sidecar. A sidecar restored without the blob store yields brush masks that rasterize empty FOREVER, indistinguishable from working ones.
- **MASK-34 — Local point curve: genuinely AHEAD of Lightroom, and provably shipping.** CREDIT, NO DEFECT. LrC 15.5 has no local tone curve. Lumen's is real on the shipping path: full Luma+RGB+R/G/B node editor retargeted per mask, second tap after picture formation through the same alpha (RenderGraph.swift:884-901), luminance-preserving default, Amount scaling displacement, covered by a GPU golden that fails if the call site is deleted (KernelGoldenTests.swift:294-318) plus CPU tests.
- **MASK-35 — Local grading wheels: AHEAD of LR in capability, UNPROVEN on the shipping path.** LrC has no local wheels. Four wheels + Blending/Balance per mask feeding the real GradeEngine on both paths, amount-scales-sat/lum-never-hue contract tested, reference-path liveness tested. But no test drives a wheel through RenderGraph — delete `if let localGrade { c = localGrade.apply(c) }` at RenderGraph.swift:1527 and the suite stays green.
- **MASK-36 — MaskKind.readsSourceImage and matteProvider ARE genuinely single sources of truth, and tested.** VERIFIED, NO DEFECT. Both exhaustive switches (RecipeMasks.swift:100-150); panel menu sections derive from matteProvider; VisionMattes.kinds filters on it; maskSource's needs-picture test reads readsSourceImage plus the Automask special case. Tests that can fail: testEveryKindAgreesAboutWhereItsMatteComesFrom, testEveryMaskKindAgreesWithWhetherItSaysItReadsThePicture. Whole-mask invert done and tested before the refine chain; fold matches maskalgebra.json.

## Could not determine
1. Whether the mask golden actually passes on the macOS runner (docs/18 records two denoise goldens sat red on macOS behind the fast lane).
2. Anything requiring Vision at runtime (MASK-15's two proposed headless tests are the settlement).
3. Real-hardware performance (MASK-29 budgets need a measuring test that does not exist).
4. The CIImage(bitmapData:) row-order convention in isolation — pinned only transitively.
5. LocalPlan's export-size cost in delivered files (MASK-02) — the 0.197-stop figure is docs/18's GLOBAL table measurement applied by analogy.

**Bottom line:** mask algebra, refine chain, overlays, local curve and local wheels are real, mostly honest, and better-grammared than LrC where they exist — but the AI roster that defines 2026 masking parity is three Vision kinds that have never executed, four empty kinds, and a lifecycle whose two ledgers already disagree; the shipping-path safety net covers exactly one mask, two sliders, and none of the wiring that feeds it.
