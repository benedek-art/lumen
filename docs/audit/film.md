# Film Lab / Look Layer / Output-Look Audit

**Method note:** all GPU-path claims are static analysis — Linux container, KernelGoldenTests are #if os(macOS).

**Where Lumen is genuinely ahead (verified, not taken from docs).** Per-channel characteristic curves in log-exposure→density space with mid-grey solved to land exactly by bisection (FilmLab.swift:1381-1409); subtractive density colour; DIR/coupler matrix; per-channel monotonicity proven across every stock × push × film-exposure × strength (EngineIntegrationTests.swift:980-1015); strength proven a true convex blend (:1020-1055). Grain is density-domain with √(p(1−p)) envelope and THREE decorrelated per-channel plates at per-channel crystal sizes on BOTH paths with tests on both sides (PipelineRenderer.swift:686-760, ReferenceRenderer.swift:398-445, goldens KernelGoldenTests.swift:118-171) — **docs/18's "one noise value in all three channels; plateScale(…,channel:) unused" is FIXED and STALE**. Film Exposure has wire (RecipeLook.swift:217), UI (LookPanel.swift:534-538), shipping reader (RenderPlan.swift:169). LR's grain is monochrome screen-space luma noise (docs/02:421-422); C1 has named grain types but no density model (docs/03:116-118); FilmPack measures renditions with no latitude model. **The engine clears the field. The findings are about what surrounds it.**

- **FILM-01 — No stock curve is checked against published data for the film it names.** UNPROVEN. FilmLab.swift:225-396 hand-authors all six. docs/05:540 and docs/14:470 claim "manufacturer datasheet digitization done by us"; NO digitized datasheet data exists in the repo (no fixture, no script, no CSV) and no test compares any FilmCharacteristic to published curves. Red flags: (a) the curve family is a SYMMETRIC logistic (FilmLab.swift:885-897) — cannot express the asymmetric toe/shoulder docs/03:955-958 says defines real stocks, so "Lumen Portra 400" cannot match Kodak's curve even in principle; (b) Portra dMin=(0.06,0.14,0.22) vs a masked C-41 negative's Status-M base+fog of roughly (0.2,0.65,0.95) — ordering right, magnitudes a third of published; (c) Gold 200 authored with RED steepest (0.605/0.590/0.578, :259) to manufacture golden highlights — a taste decision wearing an emulsion's name. Measurement: digitize Kodak Portra 400 (E-4050), Ektar 100 (E-4046), Gold 200, Tri-X 400 (F-4017), Vision3 250D (TI2621)+2383 (TI2442), Velvia 50 (AF3-960E); evaluate FilmStage.response at same log-exposure samples; assert straight-line slope and toe/shoulder density per channel as a fixture test.
- **FILM-02 — Six stocks shipped, eight specced; the halation flagship stock is absent.** MISSING. Shipped: Portra 400, Gold 200, Ektar 100, Tri-X 400, Velvia 50, Cine 250D (FilmLab.swift:398-405). docs/05:494-495 specs Portra 160, **Vision3 500T → 2383 plus its high-halation rem-jet-removed variant**, Provia 100F. The 500T variant is the CineStill-signature stock docs/03:963-966 calls the whole point of the halation model. Lumen ships a red-halation engine with no tungsten stock to use it on.
- **FILM-03 — GPU halation blurs at 3× the model's radius.** BROKEN. RenderGraph.swift:1163 `blur.radius = Float(max(sigma*3, 0.5))`. The SAME FILE at :988-1005 states as measured fact: "CIGaussianBlur.radius IS the standard deviation. Measured on the runner (2.0→2.0, 6.0→6.01, 8.95→9.0)… It was sigma*3 … that made every Gaussian three times wider — the sharpen stage's unsharp term, mask feather, **halation**." The fix landed in shared helper RenderGraph.gaussianBlur — but applyHalation (:1146-1181) never calls it; it constructs its own CIFilter.gaussianBlur() with the old ×3. Every shipping preview and export renders the glow at ~3× the 65µm-derived sigma while ReferenceRenderer.applyHalation (:366-396) renders at 1×. The comment at :988 claiming halation was fixed is FALSE. Proof missing: a golden rendering one clipped highlight through both paths comparing glow second-moments.
- **FILM-04 — The test that would catch FILM-03 cannot fail.** FAKE. KernelGoldenTests.swift:573-614 (testWhatCIGaussianBlurRadiusMeans) blurs an impulse, measures sigma — and only `print`s. ZERO assertions. Delete applyHalation entirely, or triple its radius again, and it stays green.

- **FILM-06 — Halation Size and Redness: specced, no wire format, no UI, dead engine entry point.** MISSING. docs/05:487-489 specs Amount / Size 0.5×–2× / Redness 0–100. Wire has one `halation: Double` (RecipeLook.swift:219). Comment at :1048 cites "docs/05 §8.1", a section that does not exist.
- **FILM-07 — Print size picker is a control that cannot change the picture.** FAKE. LookPanel.swift:565-572 ships a Print size menu writing FilmLab.printSize (RecipeLook.swift:221); print size cancels ALGEBRAICALLY out of plateScale, which testGrainFollowsTheGateAndTheRenderSizeNotThePrintSize (EngineIntegrationTests.swift:1175-1200) proves to 1e-12. The control the spec asked for — Grain Format 35mm/half-frame/120/off (docs/05:491), i.e. changing the GATE, the one variable that provably moves grain — does not exist; gateLongEdgeMM is frozen per stock.
- **FILM-08 — Export downsizing attenuates grain the preview never showed.** BROKEN. PipelineRenderer.export (:189-220) applies grain inside build at FULL decode resolution, THEN Lanczos-resamples to target (applyGeometry(scaleTo:)). A 6000px render downsized to 2048 averages ~9 grain samples per output pixel, cutting σ ~3×, while the 2048px preview grains at 2048 directly (:687-688). C1 applies grain AT OUTPUT RESOLUTION for exactly this reason (docs/03:116-118). No test covers it — ScaleHonestyTests never touches film (grep: zero hits). Measurement: export one flat-field recipe at native and ⅓ size, compute grain σ in a patch, compare each against equal-sized previews.
- **FILM-09 — Every photo in the library gets the identical grain plate.** PARITY-GAP. Plate seed is the constant FilmGrainProfile.defaultPlateSeed on the shipping path (PipelineRenderer.swift:694-695); nothing passes a per-photo seed (ReferenceRenderer.Inputs.grainSeed has no non-default caller). Wire (FilmGrain, RecipeLook.swift:237-240) has no seed field. The suite's own comment names the failure: "Two frames of a burst share everything except the seed, so identical plates mean identical grain — which reads as a dirty sensor, not as film" (EngineIntegrationTests.swift:1271-1284) — then tests only that the GENERATOR respects a seed nothing varies. Fix is one line of wire (seed from photo id) + format bump.
- **FILM-10 — No test proves grain reaches pixels through the shipping graph.** UNPROVEN. GPU grain goldens call PipelineRenderer.grainPlate directly and inspect the plate. Same shape as the local-curve gap; fixed for masks, not for grain.
- **FILM-11 — The shipped grain model is not the specced one; the specced entry points are dead code with a lying comment.** PARITY-GAP. docs/05:508-513: grain applies "in the density domain DURING development" against the NEGATIVE's per-channel density and dMax. - **FILM-14 — With a stock active, the whole Display Transform section is inert and the panel doesn't say so.** FAKE. So: (a) the preset picker and all four Transform-detail sliders (LookPanel.swift:397-463) move nothing while a stock is loaded, at ANY strength — at Strength 50 the blend target is Neutral, not the user's "Punchy"; (b) dragging Strength 0→1 discontinuously swaps the entire display rendition. The honest caption saying so is shown ONLY when no stock is loaded (:581-586). No test covers preset-with-stock interaction.
