## OUTPUT
- **OUT-01 — Multi-recipe export is real at the UX level, but "the render forks at the resize node" is FALSE: every checked recipe re-decodes the graph and re-renders the full develop chain.** FAKE (a stated mechanism that does not exist) on top of a genuine feature. AppStateActions.swift:127-200 loops photos × recipes, each calling PipelineRenderer.export (:188-231) which builds a fresh graph and renders end-to-end; only the RAW decode's CIImage is cache-reused. Yet PipelineRenderer.swift:210-211, ExportRecipe.swift:2-6, ExportSheet.swift:5-6 and docs/11 all state "three recipes cost one develop render plus three cheap tails." **Against C1** (docs/03 §1.9): Lumen matches the one-click multi-output gesture — which LrC still cannot do — and misses the queue and the shared render its own docs promise.
- **OUT-02 — The export queue does not exist.** MISSING. Export is a single un-cancellable Task; failures collapse to a count with no reason and no retry; quitting mid-export loses the run. docs/11's queue design (reorder/pause/persist, per-photo honest errors) and C1's reference behaviour both absent. Also absent from the sheet: per-recipe "After export", recipe sets, live size estimate.
- **OUT-03 — Export sizing: pinned by Linux MODEL tests that mirror the shipping composition — but nothing measures a written file; two of six resize modes differ from spec.** UNPROVEN + PARITY-GAP. ExportSizingTests.swift:98-137 RE-IMPLEMENTS export()'s crop→targetSize→long-edge handoff and asserts agreement within a pixel across 3 sensor shapes × 3 angles × 3 crops × 6 modes — a genuine test of the ARITHMETIC. But it is a MODEL of PipelineRenderer.swift:214-221: if export() changes composition the test keeps validating the old model; deleting the resize call in export() fails nothing. docs/19's "the RENDERED size matches" overstates: nothing was rendered. Modes shipped are none/longEdge/shortEdge/width/height/megapixels; docs/11 specifies none/long/short/**W×H**/MP/**%** — no fit-within-box, no percentage. LR ships both.
- **OUT-04 — Overwrite/collision guard and status line: implemented and honestly counted; only gap is suffix-rename as the sole policy.** PARITY-GAP (minor; core VERIFIED). - **OUT-15 — The silent-degrade defect in export is CONFIRMED, worse than a missing label — and most of it is closable WITHOUT a Mac decision.** BROKEN. Preview checks KernelLibrary.coreAvailable, falls back to renderReference, labels partial degradation. What CANNOT be done from Linux: compiling it, and testing it — KernelLibrary's static let kernels cannot be made to fail on a healthy CI Mac, so a real test needs INJECTABLE AVAILABILITY (a small refactor), after which the existing macos-15 lane covers it. docs/18's "the decision wants a Mac" is accurate only for the injectability refactor's verification, not for the policy.
