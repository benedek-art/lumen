# Native UI inspection notes

Production ContentView, AppState, CommandState and EditRevision from main 99c3727 were hosted in an audit-only macOS application. The host replaces the app entry point, injects isolated catalog/cache directories, skips the updater and production-library reopen, and adds an Audit menu with screenshot and workspace actions. It is not the distributed release bundle. Production photo views/panels were not modified.

Observed: library contact sheet; Develop on original-copy A7401502.ARW; Grade/Colour Mixer; Crop on controlled chart; mask picker, radial creation and luminosity creation; local adjustment panels; Deliver and full export sheet. Camera previews were natural, while the settled RAW decode was cyan. The first image had no XMP recipe and all basic controls were neutral. That observation was independently isolated numerically by the image agent.

Strengths: consistent quiet dark chrome, visually distinct workspaces, editable numeric pills, defaults/reset hints, per-section disclosure, an explicit embedded-preview label, histogram provenance, separate mask stack and local controls, reusable export recipes, and useful privacy defaults. Native culling navigation switched across the four audit images. Creating a luminosity mask in the relocated scratch catalog worked and exposed its overlay and undo action.

Design friction: the floating mask stack obscures photo area by default; colour/curve/detail content requires considerable vertical scrolling at the tested window size; exports contain substantial explanatory prose around routine controls; an HDR-labelled export preset/badge is offered despite all output currently being SDR. These are design observations, not measured usability-study outcomes. The Lightroom-style panel grammar is familiar, but familiarity is not correctness or proof of faster task completion.

Accessibility: the native accessibility tree exposes the thumbnail-size control as a settable float slider. Develop, grade and local LumenSlider rows instead collapse into grouped static text, without individual adjustable semantics. This was seen in more than one workspace and matches the custom-control source. VoiceOver itself was not used for a full task study.

Environment limits: initial Xcode-integrated Swift build failed signing test bundles due filesystem metadata. Native SwiftPM builds worked. SQLite catalogs under this Documents/FileProvider-backed workspace intermittently returned SQLITE_IOERR (code10), despite an external integrity_check succeeding. Moving scratch catalog/cache under a unique /private/tmp directory removed that error. It is not counted as a Lumen product defect. Some screen-capture and coordinate pointer calls failed in the automation service, so panel-divider/polygon drags and typed-value focus-loss remain source/replay findings or follow-ups, not claimed live-pointer tests. AX-index clicks and keyboard navigation worked.

Screenshots are actual AppKit captures of the production views via an audit-host command, not mockups. Screenshot filenames encode the underlying workspace; a 'crop' or 'deliver' filename can show masking because masking is a temporary mode within that workspace. The user’s original Downloads/pix files were never edited. The three RAW and two original sidecar copies still matched their source SHA-256 values at the verification point.
