## 3. The dead-control hunt

Mechanical: every `private func` / `private var` in `MaskPanel.swift` (76 of them),
counted against every reference in `Sources/` and `Tests/`.

**Result: zero private members with no call site.** `brushParameters()` — the one the
brief names — is now called from `maskDetail:413` under its own "Brush" heading, and
`componentParameters` still returns `EmptyView()` for `.brush` (`:1178-1182`), which is
the correct half of the pair. `overlayControls(_:)`, dead when docs/37 was written, is
called from `navigatorBody:203`. Both of the specific defects the brief points at are
closed.

**But the class has a live instance, one step out.** `maskThumbnail(_:)`'s doc comment
(`:846-849`) states its reason for existing:

> "Its own view rather than a method here, because the collapsed panel is nothing BUT a
> column of these — see `MaskFloatingPanel.maskRail` — and two copies of the corner
> radius and the border would have drifted the moment one of them changed."

`maskRail` does not call it (`MaskFloatingPanel:234-238` constructs `MaskThumbnail`
directly at 44×30), and neither does `maskRow` (`MaskPanel:714-717`, also direct, also
44×30). `maskThumbnail` has exactly one caller — `editingRow:243`, in the *other* panel —
and it draws 40×27. The comment names a collaborator that does not collaborate, and the
drift it was written to prevent has already happened. See **F4-04**.

Second-order dead reach, worth naming: `brushScope` (`:285`) and the whole `usesBrush`
gate are reachable only through a global index that may point at a different mask —
**F4-02**.

### F4-01 — One picker flag serves every disclosed mask: pressing "Add" opens the roster board under all of them
severity: S1
confidence: traced
class: defect
size: S
evidence: `Sources/LumenApp/MaskPanel.swift:142-143` —
`@State private var componentPickerOpen: Bool = false` / `subtractPickerOpen`; drawn per
mask at `:1036-1046` inside `componentRows(mask)`, which `maskDetail:393` calls for
**every** id in `expandedMaskIDs`. `expandedMaskIDs` is deliberately a `Set` — `:134-136`:
"A `Set` rather than one id, because 'each of them have their separate open area' means
two masks can be open at once". `kindMenu` draws a full inline board when
`isOpen.wrappedValue` is true (`:2482-2488`), not a popup.
how the owner sees it: Open two masks' chevrons. Press Add under the first. The
twelve-tile roster board appears under **both** masks, twice, pushing the second mask's
components a board's height down the card. Choosing a kind on either board adds the
component to whichever mask that board is nested in — so the second board is a live
mis-target, not just noise. This is the same defect the rebuild's own comment at
`:186-192` says it fixed one level up ("One `Bool`, two disclosures reading it: one press
flipped it and BOTH boards opened"), reintroduced by the feature that shipped this
morning.
fix: `MaskPanel.swift`. Key the flags by mask id — `@State private var
componentPickerOpen: Set<String> = []` and the same for subtract — and pass
`Binding(get: { open.contains(mask.id) }, set: …)` into `kindMenu`. Test:
`MaskPanelDisclosureTests` in the macOS lane, over a pure helper
`MaskPanel.pickerIsOpen(_ set: Set<String>, mask: String)`: with two masks expanded and
the flag set for mask A, `pickerIsOpen(open, mask: B)` must be false. Substituting the
single `Bool` back makes it true and the test red.

### F4-02 — A disclosed-but-unselected mask draws and edits the *selected* mask's component index
severity: S1
confidence: traced
class: defect
size: M
evidence: `MaskPanel.swift:2141-2144` —
```swift
private var activeComponentIndex: Int? {
    guard let m = activeMask, !m.components.isEmpty else { return nil }
    return Swift.min(Swift.max(selectedComponent, 0), m.components.count - 1)
}
```
`activeMask` is the **selected** mask (`:2131-2134`). Every child of `maskDetail(mask)`
reads it without reference to `mask`: `componentRow`'s `isSelected = index ==
activeComponentIndex` (`:1061`), `componentRows`' editor gate `if let i =
activeComponentIndex, mask.components.indices.contains(i) { componentEditor(mask.id, i,
mask.components[i]) }` (`:1049-1051`), and `usesBrush(mask)` (`:278-283`), which indexes
`mask.components[i]` with the *other* mask's `i`. The component row's tap is
`.onTapGesture { selectedComponent = index }` (`:1119`) — it never sets
`selectedMaskID`.
how the owner sees it: Select mask A (3 components, second one active). Open mask B's
chevron without selecting it. B's second row is highlighted as if chosen, B's editor is
open on its second component, and B's "Brush" section appears or not according to what
*A*'s index lands on in B's list. Now click B's third component: nothing in B changes —
the click silently moved **A**'s active component to 3, so the next Contribution drag
lands on a mask that is not the one under the pointer. The rebuild's whole thesis is at
`:137-140` — "the row selects, the chevron discloses" — and the component level never got
the second half of that separation.
fix: `MaskPanel.swift`. Make the component index per mask: `@State private var
openComponent: [String: Int]` (or move `state.activeComponentIndex` to a
`[maskID: Int]`), resolve it inside `maskDetail` as
`componentIndex(for: mask)`, and have `componentRow`'s tap set both
`selectedMaskID = mask.id` and that mask's index. Test: `MaskPanelSelectionTests`, macOS
lane, over a pure `MaskPanel.componentIndex(for:in:selected:)`: given masks A(3 comps,
idx 2) and B(4 comps), `componentIndex(for: B, selected: A, idx: 2)` must return B's own
stored index (0 by default), not 2. Substituting the global read back returns 2 and the
test goes red.

### F4-03 — ⌥-Intersect is polled from `NSEvent.modifierFlags` with nothing to invalidate the view; the label and the press can disagree
severity: S2
confidence: traced
class: defect
size: S
evidence: `MaskPanel.swift:1056` — `private var intersecting: Bool {
MaskCanvas.optionHeld() }`, and `MaskCanvas.swift:1069-1071` —
`NSEvent.modifierFlags.contains(.option)`, a synchronous global poll. It is read twice
with different timing: at body-evaluation for the label and for whether Subtract exists
(`:1036`, `:1042`), and again *inside the action closure* at press time (`:1040`
`op: intersecting ? .intersect : .add`). There is no `flagsChanged` monitor anywhere in
`Sources/LumenApp/` — `grep -rn "flagsChanged\|NSEvent.addLocalMonitor"` returns
`Keymap.swift:41` (keyDown/keyUp only) and `LumenScrollNudge.swift`. `MaskCanvas` gets
away with the same call because `.onContinuousHover` re-runs its body on every pointer
move (`MaskCanvas.swift:270-271`); the panel has no such driver.
how the owner sees it: Hold ⌥ over the panel. The button still says "Add" and Subtract is
still there, because nothing told SwiftUI to redraw — the doc comment's promise ("Holding
⌥ turns them into one Intersect button… it costs no permanent row", `:1021-1024`) does
not happen. Worse in the other direction: if the body *was* last evaluated while ⌥ was
down (say a neighbouring hover forced it) and you release ⌥ before clicking, the button
reads "Intersect" and adds an **Add** component — or the reverse. LrC's Alt-click at
creation time is the one thing gap-table F says Lumen improves on; this is the control
that was supposed to do it.
fix: `MaskPanel.swift` + one small helper. Drive it from state rather than a poll: add
`@Published var optionHeld` to `AppState`, fed by a single
`NSEvent.addLocalMonitorForEvents(matching: [.flagsChanged])` alongside `Keymap`'s
monitor, and read `state.optionHeld` in `intersecting`. Test: `KeymapModifierTests`,
Linux-safe if the monitor is behind a protocol — feed a `.flagsChanged` with `.option`
set and assert the published flag flips; assert the op chosen by
`MaskPanel.opFor(intersecting:)` equals the op the label was rendered from in the same
evaluation. Substituting the `NSEvent.modifierFlags` poll makes the two disagree and the
test red.

### F4-05 — Mask Temp claims to use the global row's axis and does not: linear Kelvin against the global's mired
severity: S2
confidence: measured
class: defect
size: S
evidence: `MaskPanel.swift:2334-2341`:
```swift
// The same range and step the global row uses. A mask's temperature is the
// same physical quantity as the picture's, and giving it a second scale
// would mean two numbers a photographer has to translate between.
optionalAdjustSlider(mask.id, "Temp", \.kelvin,
                     ColorTemperature.minKelvin...ColorTemperature.maxKelvin,
                     neutral.kelvin, step: 10, bipolar: false)
```
`optionalAdjustSlider:2352-2364` passes no `scale:` and no `trackStops:`, so it takes
`LumenSlider`'s defaults — `scale: .linear` (`LumenControls.swift:296`) and no track. The
global row is `range: 2000...50000, scale: .reciprocal, trackStops:
Lumen.temperatureStops` (`BasicPanel.swift:226-233`), and its own comment explains why:
"`.reciprocal` spends the fifths 21.4 / 33.6 / 18.8 / 15.6 / 10.5". The ranges do match
(`ColorTemperature.minKelvin = 2000`, `maxKelvin = 50000`, `ColorSpaces.swift:265-266`);
the *axis* does not, and the axis is the whole point.
how the owner sees it: On the global Temp row, 5500 K sits about two thirds along the
track and the useful daylight range occupies most of the travel. On a mask's Kelvin row,
5500 K sits at 7% and the entire 2000–10000 K range a photographer ever uses is crushed
into the first sixth of the track — every meaningful move is a two-pixel drag, and the
other five sixths are 10000–50000 K. The two controls print the same number and answer
the same drag completely differently. K-006 named this; what is new is that the code now
carries a comment asserting the opposite of what it does.
fix: `MaskPanel.swift`. Give `optionalAdjustSlider` `scale:` and `trackStops:`
parameters and pass `.reciprocal` + `Lumen.temperatureStops` for Temp,
`Lumen.tintStops` for Tint. Same edit covers K-006(b): `adjustSlider` gains `trackStops:`
and Exposure/Contrast pass `Lumen.exposureStops`/`contrastStops`. Test:
`SliderScaleTests` (LumenCore, Linux lane) already proves `.reciprocal`'s mapping; add
`MaskPanelRegisterTests` in the macOS lane asserting `MaskPanel.temperatureScale ==
BasicPanel.temperatureScale` via a shared constant — substituting `.linear` back turns
it red.
