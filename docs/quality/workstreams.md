# Lumen control audit: proposed workstreams

These workstreams go with `controls.json` / `controls.md` (256 entries, commit 5ba879f). The rule is that **no two workstreams own the same function**. Each workstream lists the functions and regions it owns. Anything shared is listed under "Shared, do not edit". A workstream that needs a change in a shared function asks the owner listed there.

Paths are relative to `/home/user/lumen`. `RG` = `Sources/LumenPipeline/RenderGraph.swift`, `PR` = `Sources/LumenPipeline/PipelineRenderer.swift`, `KR` = `Sources/LumenPipeline/Kernels.swift`, `RR` = `Sources/LumenCore/Engine/ReferenceRenderer.swift`, `RP` = `Sources/LumenCore/Engine/RenderPlan.swift`, `MP` = `Sources/LumenApp/MaskPanel.swift`, `AS` = `Sources/LumenApp/AppState.swift`.

## Ground rules that make the split work

1. **Stage chain is owned by WS-01 only.** The order of stage calls in `RR.render` (41-202), `RG.colorStageInput` (179-223), `RG.localStageInput` (117-131), `RG.build` (225-357), `PR.makeGraph` (1642-1947), `PR.renderReference` (2943-2987) and `PR.exportedImage`/`deliveredRendition` (902-1110) belongs to WS-01. A stage workstream edits only the stage function the chain calls, never the call line. If a stage needs a new argument or a new position, it asks WS-01.
2. **`RenderPlan.init` (RP 177-560) is one function with per-stage blocks** (`---- S6`, `S7`, `S9`, `S10`, `S14+S15`, `grain`, `S3`, `carried through`, tone key). Each block has one owner, named below. Changes to the shared prologue and the key memos go to WS-01.
3. **Append-only registries** (`KR` compiled-kernel list 1136-1215 and the `unavailableKernels` roster 1217+, `ControlIndex.all`, `Tests/LumenCoreTests/Proof/ProofRegistry.swift`, `SettingsSubset` groups, `WorkspaceModification`/`WorkspaceSection.reset`, `LookSubset`) are owned by WS-58. Other workstreams send their new rows to WS-58, or open separate PR hunks that touch only their own new line and rebase on top of each other.
4. **Panel view builders that hold several controls' sliders** (`BasicPanel.toneRows` 459, `presenceRows` 576, `saturationRows` 671; `DetailPanel.noiseControls` 524; `LookPanel.filmLabRows` 1439; `MP.componentParameters` 1507, `MP.adjustSections` 2139; `HealCanvas` panel body ~560-620) are **soft-shared**. A workstream may edit only its own `LumenSlider(...)`/`case` literal. Any restructure of the builder (ordering, new disclosure, a helper signature) goes to the builder's owner, named below.
5. **Recipe structs**: each workstream owns the `CodingKeys` and `init(from:)` of its own struct only. Adding a field to `Look` (RecipeLook.swift 8-124), `Develop` (Recipe.swift 331-401), `LocalAdjust` (RecipeMasks.swift 617-800) or `MaskComponent` (RecipeMasks.swift 396-578) is a hot-spot edit. It goes through WS-58, or is sequenced.
