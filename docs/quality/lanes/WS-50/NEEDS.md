# Needs from other lanes (M6: WS-50 + WS-43)

Two defects in the component algebra that this lane found and measured but cannot fix
alone. The fold's authority is `Model/MaskAlgebra.swift` and its golden
`Tests/LumenCoreTests/Fixtures/maskalgebra.json` (generated by
`scripts/gen-fixtures.py gen_maskalgebra_fixture`), both WS-42's. The GPU twin is
`KR.maskFoldSource` (`Sources/LumenPipeline/Kernels.swift:564`), lane M9's. The
CPU fold in `MaskRaster.alpha` (WS-43, this lane) has to change in the same commit
as those two, or `MaskGPUParityTests` and the golden go red. So all three go together,
in one commit, and this lane changes nothing in the fold until then.

## N1. Subtract must be `a · (1 − v)`, not `min(a, 1 − v)` (owner WS-42 + M9; WS-43 follows)

**What is wrong.** `min(a, 1 − v)` removes nothing wherever the subtracted alpha is
below `1 − a`. A 50 % subtract brush over the 40 % part of a radial's feather leaves
it at 40 %. On 8559 (radial minus a colour range on the red can), **26 % of the
pixels where both overlap (α > 0.05) are not reduced at all**, and the component's
Amount slider has a dead zone: anything from 0 up to `100·(1 − a)` does nothing.

**It also contradicts Intersect.** Intersect is already the product, so `R − C` and
`R ∩ (inverted C)` describe one selection and render differently (max |Δ| 0.242 on
8559, 0.250 on 983). A user who builds the same mask both ways gets two masks.

**Lightroom.** As far as I can tell, Adobe composites a subtract as multiply-by-complement.
I'm guessing from behaviour, not a published formula: a soft subtract brush visibly
thins the feathered fringe it crosses. Either way, `a·(1 − v)` is the only reading that
agrees with this engine's own Intersect.

**Patch** (all three in one commit):

```
MaskAlgebra.combined:   case .subtract: acc = acc * (1 - v)
MaskRaster.alpha:       case .subtract: acc.values[i] = Float(a * (1 - v))
KR.maskFoldSource:      else if (op > 0.5) { folded = a * (1.0 - v); }
maskalgebra.json:       regenerate (gen_maskalgebra_fixture, subtract case)
```

Identity is kept: `v = 0` leaves `a` exactly, and `v = 1` empties it, as before.

## N2. Component Amount 0 must be "this component does nothing" for Intersect too (owner WS-42 + M9; WS-43 follows)

**What is wrong.** `componentAlpha` scales the alpha toward 0. For Add and Subtract, 0
is the identity, so Amount 0 switches the component off. For Intersect the identity is
**1**, so Amount 0 makes `a · 0` and **empties the whole mask**, and Amount 50 halves
the mask everywhere, inside the intersected region too (`R ∩ C@50` = `0.5·R·C`; the
can's own pixels drop to 50 %). A user lowering Amount on an Intersect expects the
restriction to relax, not the whole mask to fade.

**Patch.** Fade each component toward its op's identity:

```
v = flipped(raw)                         // after component invert
add, subtract:  v' = k · v               // as now
intersect:      v' = 1 − k · (1 − v)     // k = amount / 100
```

Same three files as N1, same commit. `MaskAlgebra.componentAlpha` needs the op as an
argument (its only callers are `combined`, `MaskRaster.alpha` and `MaskGPU`'s uniform
setup). In the kernel:

```
float k = clamp(amount, 0.0, 100.0) / 100.0;
if (op > 1.5) { v = 1.0 - k * (1.0 - v); } else { v = v * k; }
```

## N3. `docs/quality/controls.{md,json}` row `mask.refine.edge` (owner: whoever maintains the registry)

The CPU column reads "boundary shift via EDT (edgeShifted :646, edt2D :1908)". After
this lane's change it is a flat dilation/erosion by an octagon
(`MaskRaster.edgeShifted` → `octagonMorphology`); `edt2D` no longer exists. The
`mask.refine.feather` row should say the guide is colour (log-luminance + OKLab a/b).
I didn't edit it because it's outside this lane's folder.

## N4. GPU refine (lane M9). Nothing needed now.

Refine is CPU-only by design (`MaskGPU.isParametric` declines any non-identity
`MaskRefine`), so this lane's refine changes need no kernel. If M9 ever moves refine
to the GPU: Expand is four sliding-extreme line passes (horizontal, vertical, two
diagonals) per integer radius plus one lerp, which maps cleanly onto separable
kernels; Follow is the three-channel guided filter in `MaskRaster.colourGuidedFilter`
(13 box filters and a per-pixel 3 × 3 solve).
